# Plan: Card Property Change Audit Log (IT-519)

## Overview
When a human user (not a bot) changes any card property — from card dialog or via Quick Actions — automatically create an "edits" type comment on that card.

## Key Requirements
- Only human users trigger this (check if modifier is bot before creating)
- Comment author = user who made the change
- Comment type = "edits" (or "bot" for bot-triggered events)
- Works for both card dialog edits and Quick Actions
- Comment aggregation: if last "edits" comment on card was created within 1 minute, append to it instead of creating new

## Comment Format Examples

**Property changed:**
```
{Property Name} changed from {old value} to {new value}
```

**Property set (was empty):**
```
{Property Name} set to {new value}
```

**Property cleared:**
```
{Property Name} changed from {old value} to Empty
```

**Person type (with @username mention):**
```
Assignee set to @johndoe
Assignee changed from @johndoe to @janedoe
```

**MultiSelect changes:**
```
Tags: added C
Tags: removed B
```

**Date/DateTime:**
- Date: `13.07.2026`
- DateTime: `13.07.2026 14:30` (24h, no seconds)

**Checkbox:** `Yes` / `No`

```go
func (a *App) PatchCard(cardPatch *model.CardPatch, cardID string, userID string, disableNotify bool) (*model.Card, error) {
    // Get current card state
    currentBlock, err := a.store.GetBlock(cardID)
    if err != nil {
        return nil, fmt.Errorf("cannot get current card: %w", err)
    }
    currentCard, err := model.Block2Card(currentBlock)

    // Get board for property schema
    board, err := a.store.GetBoard(currentCard.BoardID)

    // Validate status transitions if properties being updated
    if len(cardPatch.UpdatedProperties) > 0 {
        if validationErr := a.validateStatusTransitions(board, currentCard, cardPatch); validationErr != nil {
            return nil, validationErr
        }
    }

    // Convert to block patch and apply
    blockPatch, err := model.CardPatch2BlockPatch(cardPatch)
    newBlock, err := a.PatchBlockAndNotify(cardID, blockPatch, userID, disableNotify)
    ...
}
```

```go
func (a *App) InsertBlockAndNotify(block *model.Block, modifiedByID string, disableNotify bool) error {
    board, bErr := a.store.GetBoard(block.BoardID)
    if bErr != nil {
        return bErr
    }

    err := a.store.InsertBlock(block, modifiedByID)
    if err == nil {
        a.PopulateBlockCode(block, board)

        a.blockChangeNotifier.Enqueue(func() error {
            a.wsAdapter.BroadcastBlockChange(board.TeamID, block)
            a.metrics.IncrementBlocksInserted(1)
            a.webhook.NotifyUpdate(block)
            if !disableNotify {
                a.notifyBlockChanged(notify.Add, block, nil, modifiedByID)
            }
            return nil
        })
    }
    return err
}
```

## Potential Pitfalls and Edge Cases

### 1. Bot Detection
- **Issue:** Need to get user object to check `IsBot` field
- **Solution:** Use `a.store.GetUserByID(userID)` but handle nil user gracefully
- **Fallback:** If user lookup fails, assume human for safety (use "edits" type)

### 2. Comment Aggregation Race Conditions
- **Issue:** Two simultaneous edits might both try to append to same comment
- **Solution:** Use existing transaction mechanisms in store layer

### 3. Property Schema Changes
- **Issue:** Board property definitions might change between old and new card values
- **Solution:** Always use current board's `CardProperties` schema for both old and new value formatting

### 4. MultiSelect Diff Complexity
- **Issue:** Need to detect added and removed items separately
- **Solution:** Create set difference logic:
  - Added = new - old
  - Removed = old - new

### 5. Missing Property Definitions
- **Issue:** Property ID exists in card but not in board schema (deleted property)
- **Solution:** Handle gracefully, use raw value or property ID as name

### 6. Empty/Null Values
- **Issue:** Distinguish between "no value" and "empty string"
- **Solution:** Check for `nil` in addition to empty string

### 7. Comment Type Field
- **Issue:** `Fields` map may not exist on existing comments
- **Solution:** Initialize `Fields` map if nil before setting `commentType`

### 8. Timezone Handling for DateTime
- **Issue:** Date formatting should use user's timezone
- **Solution:** For now use UTC, can enhance later with `a.store.GetUserTimezone(userID)`

### 9. Notification Spam
- **Issue:** Creating audit comments triggers notifications
- **Solution:** Consider using `disableNotify=true` when creating audit comments (optional enhancement)

## Notes

1. **Comment Types:** The task mentions `commentType: "edits"` - this field should be stored in `Block.Fields` map as `fields: { commentType: "edits" }`

2. **Mention Format:** Person properties should use `@username` format (add @ prefix to `user.Username`)

3. **MultiSelect Diff:** Format as separate lines:
   ```
   Tags: added C
   Tags: removed B
   ```

4. **Date Format Reference:** The requirement specifies `13.07.2026` and `13.07.2026 14:30` format, which is different from the existing `January 02, 2006` format in `properties.go`. Need to create custom formatter.

5. **Aggregation Window:** 1 minute = 60,000 milliseconds

6. **Bot User for Cron:** For cron-triggered events, use @bot (bot username: `clawdbot`) as comment author

7. **Transaction Safety:** Ensure audit comment creation doesn't fail the main operation (log errors but don't return them)

8. **Store Interface:** The existing `GetBlocksWithParentAndType()` should be sufficient for finding last "edits" comment - filter in application code
